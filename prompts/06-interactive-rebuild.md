# Промт 06 v2 — полноценный сайт: маршруты, сценарии, интерактив и плавное движение

## 0. Роль и результат

Ты — инженер, который превращает опубликованную Figma-derived вёрстку в полноценный сайт.
Работай в существующем React/SSG-проекте, сохраняй визуальный характер и используй уже
реализованные компоненты. Не переписывай сайт с нуля и не добавляй анимации вместо
работающих сценариев.

Нужно получить:

1. Связную навигацию.
2. Работающие состояния: FAQ, карусели, выборы, формы, квиз, модалки.
3. Честные интеграции без фиктивной оплаты, авторизации и отправки заявок.
4. Спокойные, плавные, согласованные анимации.
5. Проверяемую сборку из редактируемых исходников.
6. Разделение конвейера и самостоятельного сайта.
7. Append-only журнал последующих указаний владельца.

## 2. Граница ответственности

Целевая схема:

```text
конвейер: экспорт → вёрстка → принятый результат
                                   │
                                   ▼
самостоятельный сайт: исходники + сценарии + motion → сборка → публикация
```

Правила:

- `reference/**` неизменяем.
- Минифицированные бандлы вручную не редактируются.
- Сайт должен собираться в собственном репозитории без соседнего checkout конвейера.
- Для React-доработки передаются исходники, конфиги и lock-файлы, а не только `dist`.
- Не переносить `.fig`, секреты, export-pack и внутренности конвейера.
- Новая выгрузка конвейера не должна затирать доработанный сайт; импорт — контролируемый,
  с provenance (commit, packId, figSha, publicationId).

## 3. Источники истины

Приоритет:

1. Последние указания владельца.
2. Принятые решения и журнал.
3. Поведение макета/прототипа.
4. Fixtures.
5. Проверенная реализация.
6. Предложение агента.

Fixtures показывают вид, но не доказывают автоплей, зацикливание, алгоритм квиза,
мультивыбор, тёмную тему, правила оплаты и доступа. Разделяй `figma`, `owner`, `proposed`.

## 4. Инвентаризация кликабельных зон

Обойди все страницы, включая вложенные:

- логотип, шапка, футер;
- CTA;
- карточки практик, форматов, мастеров, материалов;
- стрелки, точки, вкладки;
- FAQ, формы, квиз;
- вход и кабинет;
- медиа и юридические ссылки;
- thanks-страницы.

Формат записи:

```text
Страница → зона → подпись → тип действия → назначение → источник → статус → тест
```

Не используй один глобальный обработчик по тексту «Подробнее»/«Выбрать».
`data-node` допустим как переходная привязка, если проверена стабильность.

## 5. Маршруты и семантика

Единый route registry, basePath — в одной функции.

Проверять:

- корень домена и `/syntonia-site/`;
- прямой URL, refresh, Back/Forward;
- query и hash;
- вложенные `library/*`;
- unknown route → not-found, не главная.

Семантика:

- переход — `<a href>`;
- действие — `<button type="button">`;
- отправка — submit;
- якорь — существующий `id`;
- не `href="#"`, не кликабельный div вместо ссылки.

## 7. Интерактив

### FAQ
Настоящие кнопки, `aria-expanded`, связь с панелью, фокус на триггере,
закрытый контент недоступен, плавная высота, повторный клик во время анимации.

### Карусели
Один источник состояния для стрелок/точек/свайпа. Без autoplay по умолчанию.
Крайние состояния понятны, фокус не попадает в скрытые слайды, геометрия не скачет.

### Выборы
Один источник значения; вид, цена, описание и ID согласованы; клавиатура;
переход восстанавливает выбранное.

### Квиз
Шаги/ответы/переходы. Без медицинских диагнозов. При отсутствии алгоритма
показывать честный demo-result, не случайную рекомендацию.
Не сохранять чувствительные ответы в localStorage по умолчанию.

### Формы
`idle → editing → validating → submitting → success/error`.
Ошибки у полей, сохранение ввода при сбое, защита от повторного submit,
никаких ключей в клиенте, demo-режим помечен до отправки.

### Кабинет
Не имитировать авторизацию флагом в localStorage; demo-данные явно помечены.

### Модалки/медиа
Focus trap, Esc, возврат фокуса, блокировка фона, нативный `<dialog>` где возможно.
Без самозапуска звука и выдуманных видео.

## 8. Motion

Токены:

```css
:root {
  --motion-fast: 150ms;
  --motion-ui: 240ms;
  --motion-panel: 320ms;
  --motion-reveal: 440ms;
  --ease-ui: cubic-bezier(.2, 0, .2, 1);
  --ease-out-soft: cubic-bezier(.22, 1, .36, 1);
  --motion-reveal-distance: 12px;
}
```

Правила:

- не `transition: all`;
- не перезаписывать transform кодогена — отдельная обёртка/motion-слой;
- не анимировать `top/left`;
- reveal только ниже первого экрана, один раз;
- static HTML не должен быть скрыт до JS;
- без scroll-jacking, параллакса, бесконечных пульсаций;
- `prefers-reduced-motion` отключает движение, но не функционал;
- `transitionend` не должен быть обязательным для логики.

## 9. Визуал

Разделяй:

1. базовое состояние против reference;
2. интерактивные состояния против fixtures;
3. согласованные дополнения;
4. reduced-motion.

Motion имеет режим отключения для снимков (`?motion=off`), но не отключает функции.

## 10. Адаптивность

Сохраняй desktop-паритет. Без макетов не выдавай производную адаптацию за дизайн.
Устраняй overflow, недоступные кнопки, перекрытия. Проверяй 375/390/768/1440/1920.

## 11. Проверки

- все маршруты прямым URL;
- каждая страница — ожидаемый заголовок/контент;
- unknown → 404;
- assets при вложенных URL;
- hash-цели;
- basePath;
- нет `#`, пустых href, `javascript:void(0)`;
- FAQ, карусели (крайние/клавиатура/touch), выбор→переход→восстановление;
- квиз полностью, назад, смена ответа;
- формы: пустая/неверная/pending/ошибка/успех;
- модалки: фокус/Tab/Esc;
- receipt/account: без ложных подтверждений;
- pixel, hydration, reduced-motion;
- доступность и отсутствие ПДн в логах.
